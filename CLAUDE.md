# CLAUDE.md — TV Dashboard

## Architecture

Single-page React app. No backend. Data comes from one static CSV file (`public/tv_series.csv`) fetched at runtime.

**Base path (v0.4.29):** the build works at a domain root or under a sub-path (`vite build --base=/tv-dash/`, e.g. GitHub Pages) with no code change. `src/constants/paths.ts`: `BASE_PATH` (`import.meta.env.BASE_URL` minus trailing slash, `''` at root) → `createBrowserRouter(…, { basename: BASE_PATH || undefined })`; `CSV_URL` = `BASE_URL + CSV_FILE` (`resolveBase(BASE_URL, document.baseURI)`: absolute bases unchanged; a relative one (`--base=./`) is resolved once against the page the app was opened at, so the CSV URL / basename don't follow later SPA routes — relative bases still need the app opened at its folder) → `useTvData`. `CSV_FILE` lives alone in `src/constants/csvFile.ts` (no `import.meta.env`) so `e2e/fixtures.ts` can import it (`CSV_GLOB` = `**/${CSV_FILE}`, path-agnostic). **Never hardcode an absolute app URL** (`'/tv_series.csv'`, `'/index.html'`, `'/pwa-192x192.png'`) — it 404s under a sub-path; router paths (`navigate('/shows')`, `useLocation`) are basename-relative and fine. `index.html`'s `/tv.svg` etc. are rewritten by Vite. `npm run build:pages` = build with `--base=/tv-dash/` + `scripts/copy-404.mjs` (copies `dist/index.html` → `404.html`, GitHub Pages' only SPA fallback).

**Provider stack (outer → inner):**
```
RootErrorBoundary (main.tsx) → App: AppThemeProvider (theme setting + Theme contexts → ConfigProvider) → TvDataProvider → RouterProvider (createBrowserRouter) → AppLayout route [errorElement RootRouteError] → pathless PagesOutlet route [errorElement PageError] → lazy page routes
```

**Data flow:** CSV → `useTvData` hook → `TvDataContext` → pages (via `useTvDataContext()`) → components (via props).

The context object + `useTvDataContext()` live in `src/context/useTvDataContext.ts` (component-free, so Fast Refresh never recreates the context); `TvDataContext.tsx` holds only `TvDataProvider`. Pages import the hook from `useTvDataContext.ts`. The context default is `null` and the hook throws outside the provider — no fake loading state.

**CSV parsing (`src/utils/parseSeriesCsv.ts`, pure — `useTvData` only fetches, logs the returned `warnings`, exposes them as `warnings` (cleared on error), and owns loading/error state):** only `FieldMismatch` (wrong field count) errors are row-local and skip that row with a warning; `Quotes`/`Delimiter` errors are fatal — a bad quote makes Papa swallow every later line into one field and reports `row` off by one, so "skip that row" would silently lose the rest of the file. Rows with a non-positive-integer or duplicate `TV ID` are also skipped with a warning (first duplicate kept). If **every** data row is skipped, that's fatal (`CSV has no valid rows`) — not the empty state. `delimiter: ','` is fixed: Papa's auto-detect fails on an empty file. Warnings say `record N` (Nth data row), never a file line number — quoted newlines in Overview make line numbers wrong. `TV ID` is a required column. **Unknown = `null`, normalized once here:** `posNum` for `firstAirYear` / `voteAverage` / `seasons` (blank, non-numeric or ≤ 0 → `null` — TMDB's `0.0` rating means no votes), `optStr` for `language` / `ageRating` (blank or `N/A` → `null`), `posNum` for `episodeRuntime` too, and `seasons` must also be an integer ≤ 1000 (`seasonCount` — it drives an `Array.from` on Show Detail); other numbers use `num(val, 0)`. Consumers check `!= null` — never `> 0`, truthiness or `=== 'N/A'` — and render `'–'` or hide the element. Sort nullable numbers with `compareDescNullsLast` / `compareAscNullsLast` (`derive.ts` — never negate one for the other, nulls would flip to first); for the single top row use `maxBy(data, pick)` (skips nulls, first row wins ties) instead of filter + sort + `[0]`. `seasonsWatched` is deduped positive integers, so `.length` is the count. Staleness in `useTvData` is a `controllerRef` identity check (superseded by refetch or nulled on unmount), plus `mountedRef` so a retained `refetch` called after unmount is a no-op; the "timed out" message comes from a `timedOut` flag set by the timeout, not from `err.name`. On any fetch/parse error `data` is cleared to `[]` — pages check `loading` → `error` → data, and never see stale rows next to an error.

Pages always pull from context. Components always receive data as props — they do not call `useTvDataContext()` themselves. The exceptions (all intentional): `AppLayout`, `BottomNav`, `ChartsSection`, `FilterBar`, `NavProgress` and `StatsBar` call `useTheme()` directly since theme is a cross-cutting concern (card shadow, chart colors); `ThemeToggle` and `GlobalShortcuts` (the `t` shortcut) call `useThemeSetting()` (no props — `AppLayout` doesn't drill the preference); `ShortcutsHelp` calls `useTheme()` for its key caps; `ShowCard` also calls it directly for its poster-fallback background, since prop-drilling a single color through `ShowGrid` isn't worth it. `AppLayout` is also the one component that calls `useTvDataContext()` — for `warnings`, passed as a prop to `CsvWarningBanner` (shell-level, shown above every page; dismissal tied to the warnings array identity so a refetch re-shows it), and for `data` / `loading`, used only for the page title (show name on Show Detail).

## Styling

**100% React inline styles.** No CSS files in `src/`. No Tailwind, no CSS modules, no styled-components. The one CSS rule in the project is in `index.html` (`html, body, #root { height: 100%; overflow: hidden; margin: 0; }`). `index.html` also carries the favicon / `apple-touch-icon` links; `<meta name="theme-color">` is emitted by the boot plugin (kept in sync by `AppThemeProvider`) and the manifest link by `vite-plugin-pwa` at build. Exception: one **generated** inline boot script in `<head>` (see Theme System) — not hand-written in `index.html`, the `tvdash-theme-boot` plugin in `vite.config.ts` injects it.

Ant Design component styling is done via `ConfigProvider` + design tokens in `src/themes.ts`.

## Theme System

`src/themes.ts` defines the `Theme` type and 7 theme objects, in selector order: **Default Dark**, **Default Light**, **Dracula**, **High Contrast** (AAA text, chart colors + border ≥ 4.5:1 — extra test assertions), **OLED Black** (pure `#000` content + header; cards stay visible through antd's container surface + `cardShadow`), **Nord**, **Solarized Light** (accents darkened where < 3:1 on base3). System still resolves only to Default Dark / Default Light. A new theme is data only: add it to `THEME_DEFS` (incl. `tiers` / `star`) and the contract test, selector, boot script and `ThemeName` pick it up. Every color that varies by theme must come from the `Theme` object — never hardcode dark/light-specific colors.

Key `Theme` fields:
- `token.colorPrimary` — Ant Design primary color; use for `strokeColor` on `Progress`
- `token.colorTextBase?` — optional; set on Default Light to `#000000` for darker text
- `posterFallbackBg` — background for shows without a poster image
- `borderColor` — sidebar/header borders
- `chartColors[]` — 10-color array for Recharts (area charts use `token.colorPrimary` — there is no `areaFill`)
- `tiers` — `{ success, warning, danger }`, each `{ fill, onFill }`: good / medium / poor value colors (ratings, completion) and the text color on that fill (rating badges). Contract: fill ≥ 3:1 vs `contentBg`, `onFill` ≥ 4.5:1 vs fill
- `star` — the compact-list rating star (same for every rating, ≥ 3:1 vs `contentBg`)
- `isDark` — boolean, used only for Ant Design algorithm selection

`useTheme()` is the access hook.

**Typed table:** `THEME_DEFS` (private) is `as const satisfies Record<string, ThemeDef>`; `ThemeName` = its keys, `THEMES: Record<ThemeName, Theme>` adds `name` from the key (written once), `THEME_NAMES: ThemeName[]` in table order. Validate unknown input with `isThemeName(x)` (own-key type guard — `constructor` etc. are not themes), never `THEMES[x] ?? fallback`. `ThemePreference` = `ThemeName | 'System'`. `chartColors` is `readonly string[]`.

**`AppThemeProvider` (`src/ThemeContext.tsx`)** owns all theme state — `App` is only the provider stack + routes. Two contexts: the resolved `Theme` (`useTheme()`, non-null default) and `{ preference, setPreference }` (`useThemeSetting()`, throws outside the provider; `setPreference` also saves). It renders antd's `ConfigProvider` itself with `antdThemeConfig(theme, reducedMotion)` (`src/antdTheme.ts`, pure): algorithm from `isDark`, `token` + `motion`, and `colorTextLightSolid` (primary-button text — antd's fixed `#fff` otherwise) = `readableTextOn(rendered primary)` (`utils/color.ts`: white if ≥ 4.5:1, else black). It's judged on the primary antd **renders** (`theme.getDesignToken` — the dark algorithm shifts it: `#6366f1` → `#575ad0`), not the seed; white fails on Dracula / High Contrast / Nord / Solarized Light. Never assume antd derives readable text from `colorPrimary`.

**Preference vs resolved theme:** `AppThemeProvider` stores the *preference* — `SYSTEM_THEME` (`'System'`) or a theme name, read by `parseThemePreference(getSettings().themeName)` (missing / unknown / non-string → `'System'`, own-key check) and saved as `themeName`. The *resolved* theme is `resolveThemeName(pref, prefersDark)` (`'System'` → Default Dark / Default Light), with `prefersDark` from `useMediaQuery('(prefers-color-scheme: dark)')` (`src/hooks/useMediaQuery.ts`, `useSyncExternalStore` — live, no effect + setState). `ThemeToggle` shows/sets the preference (`THEME_OPTIONS`: System first, Custom last); the `Theme` context / `ConfigProvider` get the resolved `Theme`. `DEFAULT_THEME_NAME` is only the resolved fallback for `ThemeContext`'s default. It also subscribes to other tabs' theme changes (`subscribeSettings`, see localStorage → Cross-tab sync). An `AppThemeProvider` effect sets `document.documentElement.style.colorScheme` (`isDark`) and `.backgroundColor` (`contentBg`) so native controls (the `Content` scrollbar, autofill) match.

**Custom theme (v0.4.26):** `'Custom'` (`CUSTOM_THEME`) is a third kind of preference. Its settings live in a separate `customTheme` setting `{ accent: '#rrggbb', base: 'dark' | 'light' }` (kept while another theme is selected), read with `parseCustomTheme(raw)` (`themes.ts`, field by field: invalid base → dark, missing / invalid accent → the base theme's `colorPrimary`; never throws). `resolveThemeName` takes every preference except Custom (`Exclude<ThemePreference, 'Custom'>`) — Custom is built by the provider, and the boot script paints it from `CUSTOM_BASES` (Default Dark / Default Light). The resolved `Theme` is `buildCustomTheme(accent, base)` (`src/customTheme.ts` — not `themes.ts`, which must stay import-free): the base theme spread (surfaces, text, `tiers`, `star` — all contract-tested) + `name: 'Custom'`, `token.colorPrimary` = `chartColors[0]` — the accent when it's ≥ 3:1 on the base, else its lightness-corrected shade (a white accent on Light would make progress bars, highlights, `NavProgress` and area charts invisible; the picker still shows the exact accent) and `chartColors` = `customChartColors(accent, base)`: hue + i·36°, saturation clamped to 0.45–0.85, lightness started in 0.3–0.7 (L 0 / 1 would make every hue black / white), then stepped 2% away from the background until ≥ 3:1 vs `contentBg` **checked on the rounded hex** (a float at 3.0 can round below); color 0 is the accent itself when already readable. Color math (hex ↔ RGB ↔ HSL, WCAG luminance / contrast) is `src/utils/color.ts` — the one formula; `contrast.fixture.ts` delegates to it. `useThemeSetting()` also exposes `custom` / `setCustom` — the one path for every Custom change (picker drag, hex input, preset, base switch): applies live and saves `customTheme` debounced 300ms (latest value in a ref, flushed on unmount — the `ShowsPage` filter pattern). The Theme is rebuilt from `useDeferredValue(custom)`, so a drag (a new value per pointer move) doesn't re-theme the whole app every frame; the picker swatch still follows each value. `ThemeToggle` shows, only for Custom — inline from `md` up, inside a "Customize" `Popover` (`#theme-customize`, `BgColorsOutlined`) below `md` where the header can't fit picker + switch + select (the select is also 136px there) — an antd `ColorPicker` (presets deduped: OLED Black shares Default Dark's primary) (hex, no alpha, built-in primaries as presets) whose trigger is our own `Button id="theme-accent"` (`ColorPicker` takes no `id`; its default trigger isn't a focusable control) and a `Segmented id="theme-base"`. `customTheme` follows other tabs like `themeName` (applied with the raw state setter — never re-saved; unchanged values keep the same object) — **except while this tab's own change is still pending**: any other-tab write (e.g. its filters) carries the old accent, and the pending save wins anyway (`ThemeContext.test.tsx`). The `t` shortcut cycles through Custom too.

**URL theme override (v0.4.28):** `?theme=<option>` applies that selector option for the visit **without saving it**. `readThemeOverride(search)` (`themes.ts`): `URLSearchParams` (decodes `%20` / `+`), first `theme` param, trimmed, case-insensitive match against `THEME_OPTIONS` (so `System` / `Custom` work, inherited keys can't match) → canonical name or `null` (empty / unknown → ignored). `AppThemeProvider` reads it once at mount (`useState` initializer, from `window.location.search`) and uses it instead of the saved preference; nothing saves on mount, so it's never persisted. A `fromUrl` ref keeps it through in-app navigation and makes the cross-tab subscriber skip `themeName` (other tabs can't replace it; `customTheme` still syncs); `setPreference` (selector, `t` shortcut) clears it and saves as usual. A reload with the parameter still in the address bar re-applies it.

**No-flash boot script:** generated by `themeBootScript()` (`src/themeBootScript.ts` — imports only `themes.ts` / `settings.ts`; `vite.config.ts`'s `tvdash-theme-boot` plugin injects it, `transformIndexHtml`, dev + build) — an inline `<head>` script mapping each theme to `[colorScheme, contentBg]`; it resolves saved / System / invalid the same way (saved `'Custom'` → its `customTheme.base`, invalid → dark; the accent isn't needed for first paint) and sets the same two properties before the bundle loads (all in `try/catch`). With `?reset` in the URL it ignores the saved theme (same raw-segment rule as `consumeResetParam`, `RESET_PARAM`), so first paint matches the post-reset System theme. Injected with `injectTo: 'head'` — after `<meta charset>`, which must stay in the first 1024 bytes. The System dark/light pair comes from `resolveThemeName(SYSTEM_THEME, …)` and the storage key from `SETTINGS_KEY`, so nothing is retyped. It resolves in the app's order — URL override (same rule as `readThemeOverride`, inline: the script can't import), then saved `themeName` (skipped with `?reset`), Custom → saved base, System / invalid → OS — with storage and URL parsing each in `try/catch`; `themeBootScript.test.ts` runs the generated string in jsdom so it can't drift. So **`src/themes.ts` and `src/utils/settings.ts` must stay dependency-free** (no imports — both are in `tsconfig.node.json`'s `include`, with `src/themeBootScript.ts`); adding a theme there updates the script automatically.

## Shared Constants

`src/constants/ui.ts`:
- `genreTagColor(g)` — Ant Design Tag color per genre (`GENRE_COLORS` is private), `'default'` if unknown
- `ratingTierColors(v, theme)` (`{ fill, onFill }` of the rating's tier) / `ratingColor(v, theme)` (its `fill`) / `completionColor(v, theme)` — the active theme's `tiers`, picked by the pure `tier(v, high, mid)` → `'success' | 'warning' | 'danger'` (8/6 on 0–10, 75/40 on 0–100). Never hardcode tier hexes. A tier-colored badge takes one `ratingTierColors` call: `fill` as background, `onFill` as text (never `#fff`). Both take `number | null` and return `undefined` for `null` — use `ratingColor(v, theme) ?? theme.chartText` where a color is required, or pass it straight through where `undefined` inherits. Display ratings with `formatRating(v)` (`derive.ts`: one decimal or `'–'`), never inline `toFixed(1)`. `avgRating()` returns `number | null`. The small star icon in compact Dashboard lists uses `theme.star` — not tier-colored, on purpose
- `cardShadow(isDark)` — shared card shadow formula (dark vs light); use this instead of inlining the rgba values — it was duplicated across 5 files before being extracted. `cardStyle(isDark)` = `{ borderRadius: 10, boxShadow }` — spread it into a `Card`'s style instead of repeating the pair
- **Statuses:** one exported `STATUSES` table (`{ hex, tag }` per TMDB status: Returning Series, Ended, Canceled, In Production, Planned, Pilot) — add a status there once. Each hex is its tag preset's -6 shade so bars and Tags match. Index it with **literal keys only** (`STATUSES['Returning Series'].hex` / `.tag` — a typo fails to compile). `TvSeries.status` is `KnownStatus | (string & {})`: known names autocomplete, any CSV string is still accepted. `KNOWN_STATUSES` / `KnownStatus` live in `src/types/series.ts` (the data type must not import UI constants); `STATUSES` is `satisfies Record<KnownStatus, StatusStyle>`, so a status added to the list without colors fails to compile, and the list's order is `sortStatuses`' order. For a status from the CSV use `statusHex(name, theme.chartColors[i % n])` (unknown → theme chart color, same on every page) or `statusTagColor(name)`. `sortStatuses(names)` gives known-first order — FilterBar's status options come from the data through it, like genres
- **CSV-derived keys:** never index a plain object with a CSV string (`map[csvValue]`) — `constructor`/`toString` return inherited functions and skip the `??` fallback. Use the `ui.ts` helpers or `lookup(map, key)` (own-key, `src/utils/lookup.ts`), and `Object.create(null)` for count maps (see `derive.ts`)
- `PROGRESS_LABELS` / `PROGRESS_OPTIONS` — `Record<Exclude<Progress, 'all'>, string>` (FilterBar's progress select + chip; `'all'` = cleared select). Which state a show is in comes only from `progressOf(s)` (`showFilters.ts`: watched ≤ 0 → `notStarted` (a hand-edited negative count too, so in progress always means 0 < watched < total); watched ≥ total and > 0 → `completed`, so total 0 + watched = completed; else `inProgress`) — Dashboard's Continue Watching / Not Started use it too, never an inline `episodesWatched` check
- `SORT_OPTIONS` — built from `SORT_LABELS: Record<SortKey, string>` (a new `SortKey` without a label fails to compile); FilterBar's menu and ShowsPage's saved-sort validation both read it. Types `Filters` / `SortKey` / `NumericSortKey` / `Progress` live in `src/types/filters.ts`, not in `FilterBar`
- `SECTION_GAP = 24` — standard section `marginBottom`
- `SPACING` — `{ xs: 4, sm: 8, md: 12, lg: 16, xl: 24 }`

## localStorage

All persistence goes through `src/utils/settings.ts` (`getSettings()` / `saveSetting(key, value)`). Both use `SETTINGS_KEY` (`tvdash-settings`) — tests / e2e import it instead of retyping it (except `settings.test.ts`, which pins the literal: renaming it would drop users' saved settings). `getSettings()` always returns a plain object (non-object JSON → `{}`) and `saveSetting()` swallows storage errors — callers must still type-check each field they read (see `loadFilters`, `parseThemePreference`). Never read/write localStorage directly elsewhere.

**Cross-tab sync:** `subscribeSettings(listener)` (`settings.ts`, returns unsubscribe) listens to the `storage` event (fires only in *other* tabs) for `tvdash-settings` / `key === null`. The listener gets the new settings — `{}` when removed (a reset propagates) — and is **not called for a corrupt / non-object value**, so garbage never looks like a reset; `getSettings()` shares the same parser. `AppThemeProvider` subscribes: missing `themeName` → `SYSTEM_THEME`, valid → applied, invalid → ignored (unlike on load, invalid ≠ missing); a synced value is never re-saved (no ping-pong). **Shows filters are intentionally not live** — `loadFilters` runs on mount only, so another tab can't overwrite what the user is typing; they apply on the next mount **at a URL without filter params** (a Shows URL with filters shows those instead — see Shows URL state). `saveSetting` read-merge-writes, so one tab's save doesn't revert another tab's setting. A new persisted setting opts in by subscribing where it's owned.

Exception: sidebar collapsed state uses a separate `tvdash-sidebar` key directly in `AppLayout` (intentional isolation). The key name is `SIDEBAR_KEY`, defined in `settings.ts` (so the reset below knows it) and imported by `AppLayout` — never re-type the literal.

**Reset:** `resetSettings()` (`settings.ts`) removes `tvdash-settings` and `SIDEBAR_KEY`, each in its own `try`; never `localStorage.clear()` (other apps share the origin, e.g. `localhost` in dev). A new storage key the dashboard owns must be added there. Two callers: the `RootErrorBoundary` "Reset saved settings" button, and `consumeResetParam()` — `main.tsx` calls it before `createRoot`, so any URL with `?reset` clears settings before anything reads them, then drops only `reset` from the address bar (`replaceState`; raw `&`-segments, so other params stay byte-for-byte — never `URLSearchParams.delete`, which rewrites `debug` → `debug=`, `%20` → `+` — hash kept).

The `?theme=` URL override (Theme System) is never written to storage. Exception: the generated theme boot script (Theme System) reads `tvdash-settings` directly — it runs before any module, so `settings.ts` isn't loaded. Read-only; it never writes.

## Key Conventions

- **`StatCard`:** the one stat-tile component (Dashboard, StatsBar, Show Detail). `compact` = ellipsized value with the full value as hover text (built in — don't wrap it in a `title` div); its value wrapper has `minWidth: 0` so the ellipsis can work inside the flex row. Give compact tiles ≥ ~170px: Show Detail goes 4-across only from `xl`.
- **Spacing:** use `SECTION_GAP` (24px) for top-level section `marginBottom`. Inner card gutters use `[10, 10]`.
- **Row gutters:** standard outer gutter is `[16, 16]`.
- **Chart axis ticks:** `fontSize: 11` everywhere.
- **Recharts charts:** all derive calls in `ChartsSection` are `useMemo`-ized. No `Collapse` wrapper — but as of v0.4.0 the 14 charts are grouped into 4 antd `Tabs` (Overview / Watch Time / Ratings / People & Networks), each tab rendering one `<Row>` of chart `Card`s. Only the active tab's charts are mounted, not all 14 simultaneously (`destroyOnHidden`). Because panes remount, any per-chart animation state must live in a child component, not in `ChartsSection` — see `AnimatedPie` (pie legend fades in on `onAnimationEnd`; a flag in the parent stayed `true` and showed the legend during the replay).
- **React.memo:** applied to `ShowCard`, `ShowGrid`, `StatsBar`, `ChartsSection`.
- **ShowGrid columns:** uses `Grid.useBreakpoint()` (viewport breakpoints) — not ResizeObserver. Avoids layout-shift race conditions.
- **Loading/error/empty state:** data pages wrap their content in `<DataGate state={useTvDataContext()} tip=…>{data => …}</DataGate>` (`src/components/DataGate.tsx`, v0.4.37) — the one `loading` → `error` → data prelude (loading wins over a stale error; children only see loaded data). The page passes the context value in, so `DataGate` never reads context itself. Memos that need `data` go in an inner content component rendered inside the gate (Dashboard, Shows), so they don't run while loading. Below it, `<LoadingState />` and `<ErrorState />` are the shared components — never inline Spin/Alert patterns. `Spin` requires nested content when using the `tip` prop (antd v5) — never render a bare `<Spin tip={...} />`. For "no data" / "not found" cases (empty CSV on Dashboard, invalid show ID on Show Detail) use antd `Empty` directly with a contextual message + action button — there's no shared `<EmptyState />` component, each page builds its own `Empty` block inline, matching the existing pattern rather than introducing a new one.
- **Poster fallback:** every spot that shows a poster (`ShowCard`, `ShowDetailPage`, all poster thumbnails in the Dashboard sections, `src/pages/dashboard/`) uses `<VideoCameraOutlined style={{ opacity: 0.4 }} />` on `theme.posterFallbackBg`, not an emoji. `ShowDetailPage`'s hero poster and Dashboard's `PosterThumb` (covers every Dashboard thumbnail) also have an `onError` handler on the `<img>` so a broken/404 URL falls back to the same placeholder, not just an empty `posterUrl` string. `ShowCard` also renders `PosterThumb`, so it covers broken/404 URLs the same way.
- **PWA / offline (production only):** `vite-plugin-pwa` (`generateSW`) in `vite.config.ts` — `registerType: 'prompt'`, `injectRegister: false`; manifest colors from the System-dark theme (`headerBg` / `contentBg`, imported from `themes.ts` like the boot script); icons in `public/` (`pwa-192x192.png`, `pwa-512x512.png`, `pwa-maskable-512x512.png`, `apple-touch-icon.png`, generated once from `public/tv.svg` — regenerate them if the SVG changes). Precache = the built shell (`globPatterns` js/css/html/svg/png/ico minus `globIgnores: ['pwa-*.png']` — the manifest icons are fetched only at install, `includeManifestIcons: false`; the plugin adds `manifest.webmanifest` itself — don't add it to the globs); `navigateFallback: 'index.html'` (relative — resolved under the base) for offline deep links; manifest `start_url` / `scope` are left to the plugin (= Vite's base) and icon `src`s are relative (resolved against the manifest URL). **`tv_series.csv` is never precached** — runtime `NetworkFirst` (matched by `pathname.endsWith('/tv_series.csv')`: the pattern is serialized into `sw.js`, so it can't import `CSV_FILE`, and must match under any base), 8s timeout (a slow-but-online fetch must not silently fall back — no notice shows while online), cache `tvdash-data`, 1 entry, 200 only; `navigateFallbackDenylist` skips URLs with a file extension so `/tv_series.csv` opened in a tab is the file, not the app's 404; `useTvData` is unchanged (its 10s timeout stays the outer limit). **Posters are not cached** (opaque cross-origin responses blow up quota). Shell: `UpdatePrompt` (`useRegisterSW` → antd `notification` hook form, "New version available" + Reload → `updateServiceWorker(true)`; checks for a new build hourly and whenever the tab becomes visible — an installed window gets no navigations; a dismissed prompt comes back on the next visibility; `onNeedReload` reloads only the tab that clicked — other tabs get "updated in another tab — Reload" instead of an unannounced reload that would drop e.g. a pending debounced filter save) and `OfflineNotice` (`useOnlineStatus()`, `useSyncExternalStore` on `online`/`offline`, its own component so a flip re-renders only it; "Offline — showing saved data" only with `hasData`, else "You're offline") above `CsvWarningBanner`. **The crash screen can't rely on `UpdatePrompt`** (it lives in the shell that crashed): `RootErrorBoundary`'s default Reload first calls `activateWaitingServiceWorker()` (`src/utils/serviceWorker.ts` — posts `SKIP_WAITING` to a waiting worker, waits for `controllerchange`, 3s cap, never throws), so a deployed fix actually loads; a plain reload would keep serving the precached broken build. `AppThemeProvider`'s document effect also sets `meta[name=theme-color]` to `headerBg` (the `tvdash-theme-boot` plugin emits the meta itself — System-dark `headerBg` from `THEMES`, no literal in `index.html` — and its script sets the resolved theme's `headerBg` before first paint). In dev the plugin serves a no-op register module; **Vitest can't load the virtual module id**, so `vitest.config.ts` aliases `virtual:pwa-register/react` to `src/components/pwaRegister.fixture.ts`. `?reset` / `resetSettings()` never clear the SW or Cache Storage (README troubleshooting: clear site data). Types: `src/vite-env.d.ts` references `vite-plugin-pwa/react`.

- **`react-hooks/set-state-in-effect`:** this project runs `<React.StrictMode>` (`src/main.tsx`). React's own documented workaround for this lint rule — "adjust state during render" (compare a prop/derived value against a `last*` state value, call `setState` in the render body when it differs, skip the `useEffect`) — genuinely misbehaves here: confirmed via a debug trace (`BottomNav`'s re-show on pathname change — moved from `AppLayout` in 0.4.13; `ShowDetailPage`'s `overviewExpanded` reset; its poster error is URL-keyed like `PosterThumb`, so it needs no reset) that it oscillates across StrictMode's double-render and settles on the wrong value. Both spots use a plain `useEffect` with `// eslint-disable-next-line react-hooks/set-state-in-effect` + a comment. If you hit this rule elsewhere, don't reach for the render-time-adjustment pattern by reflex — verify it against a real navigation/prop-change in the browser before trusting it, or just suppress the rule.

## CSV Generator (series-search.py)

Standalone Tkinter script, outside the React app, used to build/maintain `public/tv_series.csv` via the TMDB API. It writes `CSV_PATH` = `<script dir>/public/tv_series.csv` (not the working directory). `FIELDNAMES` is the column contract with `parseSeriesCsv.ts`; appends follow the existing file's header (warning about missing columns). Unknown values are written as `''`, not `'N/A'` (older rows may still hold `'N/A'` — the app handles both). Structure (0.4.13): `TmdbClient(api_key, session=None)` (HTTP + details cache; the key is sent per request; `get()` is the one place failures become `TmdbError` with the key redacted — `redact()`, `from None` so the traceback doesn't print the URL either — so `App` just shows `str(err)`), `CsvStore` (CSV I/O, path passed in), `App(root, client, store, dialogs=messagebox)` (Tk), `main()` behind `if __name__ == "__main__"` — importable with no side effects. **Threading rule:** every TMDB call runs in a worker (`App.run_bg(work, on_done)`, or `App.post(cb, …)` from inside a worker); workers never touch Tk — results come back through `App._results`, a queue the Tk loop polls every 30ms **only while a `run_bg` job is pending** (`_pending`; idle = no timer) — so `post()` is only valid from inside a running job, so widgets/dialogs stay on the main thread and the window never freezes. Don't call `root.after` from a worker. `loading` (search + details) blocks search/paging; `saving` (detail + season fetches of a save) disables Save. `current_page` / `total_pages` / `query` only change after a fetch succeeds, and Next/Prev page through `query` (the last successful search), not the entry text. Season fetches run in parallel (pool of 4). A failed season fetch is skipped and reported (`Partly Saved` / `Not Saved` / in `Updated`), never saved as 0 episodes. The row is re-read right before writing and **only seasons it doesn't already have are counted** (two panels / a hand edit can't double episodes; nothing new → `Already Saved`). `CsvStore` reads with `utf-8-sig` (Excel's BOM would hide every existing row → duplicate appends) and `update()` writes a temp file + `os.replace` with `extrasaction="ignore"` (a crash or a hand-edited extra-field row can't truncate the CSV). An exception in any `on_done` callback (e.g. `PermissionError`, CSV open in Excel) shows an error dialog and re-enables the UI — never only a console traceback. Reads `TMDB_API_KEY` from the environment — never hardcode the key, it must not land in git history.

Vitest's default environment is **node** (`vitest.config.ts`, which merges `vite.config.ts`). ## Lock File

If `package.json`'s `version` (or any dependency) is bumped by hand, run `npm install` immediately after so `package-lock.json` resyncs — a stale lock passes `npm install` silently but fails `npm ci` in CI. This bit us once: `vitest`'s nested `vite@8` needs a separate `esbuild ^0.27||^0.28` tree from the top-level `vite@5`'s `esbuild ~0.21`, and a stale lock had them wrongly deduped. **Regenerate the lock with CI's npm (Node 20 → npm 10): `npx -y npm@10 install`.** That nested esbuild is an *optional peer* of `vite@8`; newer local npm (12) leaves `node_modules/vitest/node_modules/esbuild` out of the lock, and npm 10's `npm ci` then fails with `Missing: esbuild@0.28.x from lock file` (happened again in 0.4.11). Check: `grep vitest/node_modules/esbuild package-lock.json`.

## Project Docs

- `IDEAS.md` — top: `## Open follow-ups`, then `## Improvement Ideas` (one `###` section per module, `#### P1` / `P2` / `P3`: high value + low cost / worth doing / experimental). **Each idea lives once**, in the module that owns it; related modules point to it instead of repeating it. Bottom (after `---`): `## Completed` — finished Next Up list + per-module review tracker, kept for history. When an idea ships, move it into `## Completed` (or strike it through) rather than deleting it.
- `BUG_BACKLOG.md` — `## Open` (unchecked, each bug-like idea cross-referenced to its `IDEAS.md` entry) then `## Fixed in <version>` blocks, newest first.
- `openspec/` — OpenSpec workflow (`/opsx:propose` / `apply` / `archive`): `specs/<capability>/spec.md` are the main specs (behavior contracts — `theming`, `page-titles`, `app-recovery`, `motion-preferences`, `semantic-colors`, `settings-sync`, `route-prefetch`, `offline-support`, `navigation-feedback`, `keyboard-shortcuts`, `custom-theme`, `builtin-themes`, `theme-url-override`, `subpath-hosting`, `shows-url-state`, `shows-filters`, `cross-navigation`, `time-left` so far), `changes/<name>/` open proposals (proposal / design / delta specs / tasks), `changes/archive/YYYY-MM-DD-<name>/` shipped ones. Archiving syncs a change's delta specs into `specs/`. When a change ships, also update the other docs in this list like any other feature.
- `CHANGELOG.md` — one `## [x.y.z] — date` block per version, newest first. `features.txt` — user-facing feature list with a `Version x.y.z` header.
- **On a version bump:** `package.json` `version` → `npx -y npm@10 install` (see Lock File) → `CHANGELOG.md` → `features.txt` header → move fixed items in `BUG_BACKLOG.md` → `IDEAS.md` "Last updated" line → README if user-facing.
